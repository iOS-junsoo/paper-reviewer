# 논문 방법론 인터랙티브 시각화 — 제작 지침서

이 문서는 ML 논문 리뷰 웹사이트의 "연구 방법론" 탭에 들어갈 **논문 1편당 1개의 독립 실행형 HTML 시각화 파일**을 제작하기 위한 완전한 지침이다. 이 지침만 보고 구현 모델이 일관된 품질의 파일을 만들 수 있도록, 확정된 규칙·수치·검증 절차·알려진 함정을 모두 담았다.

---

## 0. 산출물 정의

| 항목 | 스펙 |
|---|---|
| 형태 | 논문 1편 = HTML 파일 1개 (외부 의존성 0, CDN·이미지·폰트 파일 없음) |
| 규모 | 260~400줄 내외. 단일 `<script>` 블록, 단일 `<style>` 블록 |
| 대상 독자 | 그 논문을 처음 읽는 사람. 방법론을 "빠르게, 쉽게, 그러나 구체적으로" 이해시키는 것이 목적 |
| 언어 | 한국어 (수식·용어는 원문 병기 가능) |
| 필수 구성 | ① 헤더(제목+타입 배지+3~4문장 lead) ② 좌측 구조도 ③ 우측 데이터 여정 패널 ④ 스테퍼 ⑤ 하단 인터랙션 실험실 ⑥ 정직성 캡션(note) |
| 금지 | 드릴인(클릭해서 펼치는 구조) 전면 금지. 구조도는 모든 하위 단계가 처음부터 펼쳐져 있어야 한다 |

**드릴인 금지 이유**: 처음 읽는 독자는 어디를 클릭해야 할지 모른다. 전체 구조가 한눈에 보이고, 스테퍼가 현재 단계만 강조(나머지는 흐리게)하는 방식이 확정 규칙이다.

## 1. 타입 분류 체계

논문을 받으면 먼저 아래 9개 타입 중 하나로 분류한다. 분류가 시각화의 뼈대를 결정한다.

| 타입 | 이름 | 기준 질문 | 대표 예 |
|---|---|---|---|
| T1 | 아키텍처 제안 | 새로운 신경망 전체 구조를 제안하는가? | Transformer |
| T2 | 모듈 제안 | 기존 망에 끼워 넣는 부품(블록)을 제안하는가? | SE-Net |
| T3 | 손실·목적함수 제안 | 학습 신호(손실)의 설계가 핵심인가? | SimCLR |
| T4 | 압축·경량화 | 모델을 줄이는 방법(프루닝·양자화·증류)인가? | FairGRAPE |
| T5 | 데이터 중심 | 모델·손실은 그대로 두고 데이터를 바꾸는가? | mixup |
| T6 | 생성 모델 | 데이터를 생성하는 확률 과정을 배우는가? | DDPM |
| T7 | 시스템·파이프라인 | 여러 컴포넌트를 조립한 시스템인가? | RAG |
| T8 | 이론·현상 | 새 방법이 아니라 현상·성질의 발견/분석인가? | Grokking |
| T9 | 벤치마크·평가 | 데이터셋·지표·평가 절차의 제안인가? | BOLD |

### 분류 결정 트리 (위에서부터 순서대로 적용)

1. 새 방법 제안 없이 현상 발견·분석이 핵심 → **T8**
2. 데이터셋/지표/평가절차 제안이 핵심 → **T9**
3. 여러 독립 컴포넌트(검색기+생성기 등)의 조립 → **T7**
4. 생성 확률 과정(노이즈→데이터, 잠재→데이터) 학습 → **T6**
5. 모델 크기 축소가 목적 → **T4**
6. 모델·손실 불변, 데이터 변형만 → **T5**
7. 손실 함수 설계가 기여의 중심 → **T3**
8. 기존 망에 삽입하는 부품 → **T2**
9. 전체 아키텍처 제안 → **T1**

주의: 복수 해당 시 **논문 스스로 주장하는 핵심 기여(보통 abstract의 "we propose" 문장)**를 따른다. 예: SimCLR은 프레임워크(시스템처럼 보임)지만 기여의 중심은 NT-Xent 손실과 그 요소 분석이므로 T3.

### 9개 타입에 없는 논문 처리

§5(미지 타입 폴백)를 따른다. 요약: ① 가장 가까운 타입에 매핑 시도 → ② 실패 시 범용 골격(공통 템플릿 그대로 + "방법의 데이터 흐름"을 6단계로 재구성) 사용. 어떤 경우에도 공통 템플릿(§2)과 정직성 규칙(§6)은 동일하게 적용된다.

## 2. 공통 템플릿 (전 타입 동일)

### 2.1 레이아웃

```
┌──────────────────────────────────────────────┐
│ h1 제목 + 타입 배지        lead 문단(3~4문장)     │
├───────────────────┬──────────────────────────┤
│ 좌: 구조도 SVG      │ 우: 데이터 여정 패널          │
│ (col-struct,      │ (col-journey)             │
│  flex 0 0 400~460)│  STEP 배지 / h3 / 설명 /    │
│                   │  shape 배지 / 미니 시각화     │
├───────────────────┴──────────────────────────┤
│ 스테퍼: ◀이전 · 점(dot) · n/N · 다음▶ · ▶자동     │
├──────────────────────────────────────────────┤
│ 실험실(lab): 슬라이더·토글·버튼으로 핵심 파라미터 조작  │
│ note: 정직성 캡션                               │
└──────────────────────────────────────────────┘
```

### 2.2 테마 (버건디/크림 고정)

```css
:root{
  --bg:#faf6f0; --card:#fff; --ink:#3b3231; --ink-soft:#8a7d79;
  --accent:#8c2f39; --accent-soft:#b56a70; --accent-faint:#f4e6e4;
  --line:#e8ddd4;
}
```
보조색은 타입별 의미에 맞게 2~3개만 추가(예: 검색=파랑 #5b8bb0, 생성=초록 #7a9e6b, 문서=황토 #c99b4e). 폰트는 시스템 스택: `-apple-system,"Pretendard","Noto Sans KR",sans-serif`, 제목만 `Georgia,"Noto Serif KR",serif`.

### 2.3 구조도 + 존(zone) 하이라이트

- 구조도의 각 단계를 `<g class="zone" data-zone="i">`로 감싼다. 존 개수 = 스텝 개수(기본 6, T8처럼 국면형은 4 허용).
- 현재 스텝의 존만 `hot`(drop-shadow 강조), 나머지는 `dim`(opacity .28).
```css
.zone{transition:opacity .35s;} .zone.dim{opacity:.28;}
.zone.hot .zbox{filter:drop-shadow(0 0 6px rgba(140,47,57,.5));}
```
- 컨테이너 배경 rect(예: "인코더 ×6" 틀) 위에 내부 박스·텍스트가 얹히는 것은 허용(문서 순서상 텍스트가 나중 = 위에 렌더).

### 2.4 데이터 흐름 입자 (전 타입 동일 수치)

- 구조도에 보이지 않는 경로 `<path id="flowpath" fill="none" stroke="none">`를 깔고, 입자 4개가 **항상 전체 경로**를 흐른다. 스텝과 무관하게 상시 재생.
```js
[0,0.25,0.5,0.75].forEach(off=>{ /* r=3.4 circle 생성 */ });
function tick(){ p.off+=0.0021; /* getPointAtLength로 위치 갱신 */ }
```
- `prefers-reduced-motion: reduce`면 입자 숨김(CSS)과 tick 미기동 둘 다 처리.

### 2.5 스테퍼

- 이전/다음/자동(3.0~3.2초 간격 setInterval, 재클릭 시 정지) + 점(dot) 직접 클릭.
- 스텝 전환 시: 존 하이라이트 갱신 → STEP 배지·제목·설명·shape 배지 갱신 → 우측 미니 시각화 재렌더.
- 각 스텝은 `{zone, t(제목), d(설명 2~4문장), sh(shape 문자열), v(미니 시각화 렌더 함수)}` 객체.
- shape 배지에는 그 단계의 텐서/데이터 형태를 쓴다(예: `3 × 512`, `1×1×C`, `λ~Beta(α,α)`).

### 2.6 실험실 (타입별 1개 이상 필수)

- 논문의 **핵심 하이퍼파라미터/개념 축** 하나를 골라 슬라이더·토글·버튼으로 조작하게 한다.
- 조작 → 시각 반응은 즉각적이어야 하며, 수치 표시는 `font-variant-numeric:tabular-nums`.
- **막대/게이지의 2단계 애니메이션 규칙**: 새 DOM을 만들 때 폭/높이를 0으로 넣고, `requestAnimationFrame` 안에서(필요시 이중 rAF) 최종값을 설정해 CSS transition이 걸리게 한다. 최종값을 생성 시점에 바로 넣으면 전이가 발생하지 않는다.
- **막대 요소는 반드시 `display:block`**(span 사용 시). inline 상태에선 width/height가 무시되어 막대가 아예 렌더되지 않는다 — 실제로 발생했던 버그다.

### 2.7 미니 시각화(데이터 여정)의 막대·볼륨 규칙

- 값 막대는 **바닥(baseline) 고정, 위로 성장**. 상단 고정 후 아래로 자라게 그리면 안 된다(크기 비교 직관 붕괴 + 캡션 침범 — 실제 발생 버그).
- 캡션·값 라벨은 baseline **아래** 전용 여백에 배치. viewBox 세로를 여유 있게(예: 300×165) 잡고 `막대바닥 < 값라벨 < 캡션 < viewBox하단` 순서를 지킨다.

### 2.8 기존 서비스의 패널 리사이즈와의 호환 (필수 준수)

**전제**: 실제 서비스에는 이미 사용자가 패널 크기를 드래그로 조절하는 리사이즈 기능이 있다. 시각화를 이식할 때 **이 리사이즈 동작을 깨뜨리지 않고, 어떤 크기로 조절돼도 시각화가 정상 표시되어야 한다.** 리사이즈 기능을 새로 만드는 것이 아니라, 그 안에 들어가도 견디는 시각화를 만드는 것이 요건이다.

**리사이즈를 견디기 위한 필수 조건**(참조 구현 9개는 아래를 이미 만족한다):
1. **모든 SVG는 고정 px 폭이 아니라 `width:100%` + `viewBox`로 그린다.** 그러면 부모 패널이 리사이즈될 때 SVG 좌표계 전체가 자동으로 비율 스케일된다. 고정 `width="430"` 같은 절대폭을 쓰면 리사이즈에 반응하지 못한다.
2. **좌표 계산은 화면 픽셀이 아니라 viewBox 논리좌표로 한다.** 입자 경로(`getPointAtLength`), 산점도 좌표, 막대 위치 등은 전부 viewBox 내부 좌표(예: 0~430) 기준으로 계산한다. 그러면 리사이즈로 스케일이 바뀌어도 상대 위치가 유지된다.
3. **레이아웃은 flexbox 비율(`flex:1`, `flex:0 0 Npx`)로.** 절대 위치(`position:absolute` 좌표 고정)로 패널을 배치하지 않는다. 리사이즈 시 flex가 재분배한다.
4. **`getBoundingClientRect`(실제 픽셀 측정)에 의존하는 로직을 리사이즈 중 재실행되는 경로에 두지 않는다.** 1회성 초기화에만 쓰거나, 꼭 필요하면 `ResizeObserver`로 감싼다.

**주의점(가독성)**: `viewBox` 스케일 방식은 패널이 아주 좁아지면 텍스트·요소가 통째로 축소되어 읽기 어려워질 수 있다. 서비스의 리사이즈 최소 폭이 좁다면, 극단적 크기에서 텍스트가 뭉개지지 않는지 실제 리사이즈해 확인하고, 필요하면 최소 폭 이하에서 레이아웃을 세로로 접는 브레이크포인트나 `ResizeObserver` 기반 폰트 보정을 추가한다.

**이식 시 하지 말 것**: 시각화 컨테이너에 고정 `width`/`height`(px)를 박거나, 바깥 서비스의 리사이즈 핸들·스플리터를 덮어쓰는 CSS(예: 패널에 `resize:none`, `overflow:hidden`으로 핸들 가림)를 넣지 말 것.

## 3. 타입별 상세 스펙

각 타입의 ① 구조도 형태 ② 스텝 구성 ③ 실험실 조작 축 ④ 입체(2.5D) 등급을 정의한다. 등급은 §4 기준으로 A(순수 2D) / B(전면 2.5D isometric) / C(구조도만 살짝 입체) 중 하나.

### T1 아키텍처 제안 (예: Transformer) — 등급 C
- **구조도**: 전체 아키텍처를 세로 흐름으로 전부 펼친다. 반복 블록(×N)은 **슬랩 N장 스택**으로 표현(맨 앞 슬랩에 서브층 배치, 뒤 슬랩은 dx≈4, dy≈-5 오프셋으로 겹침). 인코더-디코더 간 연결(K,V 전달 등)은 별도 화살표.
- **스텝**: 데이터 입장에서 통과 순서대로 6~8단계(임베딩→각 서브층→출력).
- **여정**: 실제 짧은 예문(가능하면 논문의 예문)이 각 단계에서 어떤 shape로 변하는지.
- **실험실**: 논문의 핵심 메커니즘 직접 조작(Transformer면 어텐션: 쿼리 토큰 클릭 + √d_k 스케일 슬라이더, 논문의 유명 예문 사용).

### T2 모듈 제안 (예: SE-Net) — 등급 B
- **구조도**: 부품 내부의 데이터 볼륨 변형을 isometric 큐보이드로. 볼륨이 눌리고(GAP) 얇아지고(병목) 되살아나는(재조정) 형태 변화가 핵심.
- **필수 인셋**: "이 부품이 기존 망 어디에 꽂히는가" 미니 다이어그램(예: SE-ResNet의 잔차 분기, identity 합산 전).
- **실험실**: 부품의 구조 하이퍼파라미터(SE면 reduction ratio r) + 그에 따른 파라미터 수·동작 변화.
- **isometric 헬퍼(재사용)**: `cuboid(g,x,y,w,fh,d,face,top,side)` — (x,y)=정면 좌상단, 깊이 투영 IX=0.86, IY=0.5. 윗면→옆면→정면 순서로 그림. 채널 스택은 `slabStack()`.

### T3 손실·목적함수 제안 (예: SimCLR) — 등급 A
- **구조도**: 손실이 계산되기까지의 파이프라인(병렬 2-lane 가능) + gradient 회귀 점선.
- **실험실**: **손실이 표현 공간에 가하는 힘의 물리 시뮬레이션**. 대조학습이면 anchor/positive/negative 점들이 실제로 당겨지고 밀쳐지는 애니메이션 + temperature 등 손실 파라미터 슬라이더. "학습 스텝" 버튼으로 힘 1회 적용.

### T4 압축·경량화 (예: FairGRAPE) — 등급 C
- **구조도**: 절차 루프(중요도 계산→선택→제거→fine-tune→반복)를 명시. 반복 화살표 필수. 망 그래프는 노드에 층별 z-오프셋(dz≈14)+타원 그림자로 살짝 입체.
- **여정**: 망 그래프에서 연결이 점선으로 죽어가는 모습 + 기준(중요도) 막대.
- **실험실**: **압축률 슬라이더 + 베이스라인 대비 비교 패널**(일반 방법 vs 제안 방법을 나란히). 방향 주의: 슬라이더 값↑ = 더 많이 제거.

### T5 데이터 중심 (예: mixup) — 등급 A
- **구조도**: 데이터 변형 파이프라인(입력들→변형 규칙→가상 샘플→기존 학습 투입). "모델·손실은 그대로"를 명시.
- **실험실**: 변형 파라미터(λ, α) 직접 조작 → **입력과 라벨이 같은 비율로 함께 변하는 것**을 나란히 표시. 분포(Beta 등)는 실제 확률밀도를 계산해 그림.
- **필수 패널**: "왜 되는가" — 논문이 제시한 효과 그림(mixup이면 결정경계: 일반 학습=급격·진동 vs 제안=부드러운 전이대)을 정성 재현.

### T6 생성 모델 (예: DDPM) — 등급 C
- **구조도**: 정방향(데이터→잠재/노이즈)과 역방향(잠재→데이터)의 **양방향 체인**을 위·아래 두 행으로. 체인의 각 상태를 실제 열화/복원 수준이 반영된 타일로 그리고 그림자만 살짝.
- **실험실**: 잠재 정도(t, 노이즈 레벨 등) 슬라이더 → 상태 타일 실시간 변형 + 스케줄 곡선(ᾱ 등)은 **논문 스케줄로 실제 계산**해 그리고 현재 위치 마커 표시.

### T7 시스템·파이프라인 (예: RAG) — 등급 A(+색인 더미)
- **구조도**: 컴포넌트 단위 세로 파이프라인. 대용량 저장소(문서 색인 등)는 문서 더미(타일 3장 스택) 아이콘으로 규모감. 보조 입력 경로(질의가 생성기에도 직접 감)는 점선.
- **실험실**: 시스템의 조립 파라미터(top-K 등) 조작 → 선택 결과 리스트가 2단계 애니메이션으로 갱신. 공간 검색(MIPS 등)은 산점도로 표현하되 **화면상 거리 순위 = 점수 순위가 되도록 좌표를 점수 기반으로 계산**(임의 배치 금지 — 불일치 버그 실제 발생).
- **변형 개념**(RAG-Sequence/Token처럼 복수 모드)이 있으면 여정 스텝에 시각적으로 구분(토큰별 참조 문서 색 밑줄 등).

### T8 이론·현상 (예: Grokking) — 등급 A
- **구조도 없음**: 현상을 보여주는 **곡선/차트가 주인공**. 좌측에 차트, 우측에 국면 설명.
- **스텝**: 파이프라인이 아니라 **국면(phase)** 4개 내외. 각 국면에서 차트 위 세로 마커가 이동하고 관련 수치가 갱신.
- **실험실**: 시간축(스텝) 슬라이더 + 현상에 영향 주는 요인 토글(weight decay 등) + "재생" 버튼(rAF 애니메이션). 곡선 모델은 논문이 보고한 정량 경계(예: 훈련 <10³ 포화, 검증 ~10⁶ 도달)를 만족해야 한다.
- 로그축 사용 시 **음영·마커가 plot 영역을 넘지 않게 클램프**(실제 발생 버그).

### T9 벤치마크·평가 (예: BOLD) — 등급 A
- **구조도**: 평가 파이프라인(수집→프롬프트 추출→모델 생성→지표 채점→집계).
- **여정**: 논문의 실제 예시 데이터(실제 프롬프트, 실제 표 예시)가 각 지표에서 채점되는 과정.
- **실험실**: 지표 × 도메인 선택 세그먼트 → 논문의 **실제 수치**로 그룹 간 비교 막대. 막대는 2단계 애니메이션 + display:block.

## 4. 입체(2.5D) 적용 판단 기준

핵심 질문 하나로 결정한다: **"깊이 축이 데이터의 실제 3번째 차원과 대응하는가?"**

| 등급 | 조건 | 적용 방식 | 예 |
|---|---|---|---|
| B (전면 2.5D) | 데이터 자체가 부피(H×W×C 등)이고 방법의 핵심 동작이 그 축을 따라 일어남 | 구조도·여정 모두 isometric 큐보이드 | SE-Net(공간을 눌러 채널만 남김) |
| C (구조도만 살짝) | 데이터는 2D지만 구조에 실재하는 반복/적층/사슬이 있음 | 구조도 해당 요소만 슬랩 스택·그림자·z-오프셋. 여정·실험실은 2D 유지 | Transformer(×6 반복), FairGRAPE(망 층), DDPM(시간 사슬) |
| A (순수 2D) | 부피도 적층도 없음: 행렬, 임베딩 공간, 함수 곡선, 파이프라인 | 2D | SimCLR, mixup, RAG, Grokking, BOLD |

**금지**: 범주형 값 비교 막대(그룹별 정확도 등)에 입체를 넣지 말 것. 깊이가 무의미한 장식이 되고 높이 비교(핵심 과업)를 왜곡한다. 등급 B/C라도 값 비교 차트는 항상 2D.

## 5. 미지 타입 폴백 (9개 타입에 안 맞을 때)

1. **최근접 매핑 시도**: 결정 트리(§1)를 완화 적용해 가장 가까운 타입의 골격을 빌린다.
   - 최적화 기법(새 옵티마이저, LR 스케줄) → T3 골격(학습 신호가 파라미터 공간에 가하는 힘의 시뮬레이션)
   - 프롬프팅·인컨텍스트 기법 → T7 골격(입력 조립 파이프라인)
   - 해석가능성·분석 논문 → T8 골격(발견된 현상의 차트 + 국면)
   - 파인튜닝·어댑터(LoRA 등) → T2 골격(기존 망 어디에 무엇이 꽂히나 + 인셋)
   - 강화학습 방법 → T7(에이전트-환경 루프 파이프라인) 또는 T3(보상 신호가 정책에 가하는 힘)
2. **매핑 실패 시 범용 골격**: 공통 템플릿(§2) 그대로 + "방법의 데이터 흐름"을 저자 관점에서 6단계로 재구성(입력→핵심 변환 3~4개→출력→학습 신호). 실험실은 논문 ablation에서 가장 큰 영향을 보인 파라미터 1개를 슬라이더로.
3. 폴백 사용 시 PROGRESS 주석에 "폴백: X 골격 차용, 근거: ..."를 남긴다.

### 6.2 Figure 캡션 추출 (설계 전 필수)
- 본문만 읽지 말고 **Figure 캡션을 전부 추출**한다(`pdftotext` 후 `Figure N[.:]` / `Fig. N[.:]` 두 패턴 모두 검색).
- **저자의 Figure 1~2는 저자가 승인한 멘탈모델**이다. 구조도의 위상은 이를 따르고, 지침의 인터랙션을 얹는다.
- Figure 캡션에서 "왜 되는가"류 그림(효과·비교·경계)을 발견하면 해당 패널을 추가한다(예: mixup Fig.2 결정경계, RAG Fig.2 토큰별 문서).
- 이미지 렌더가 가능하면 `pdftoppm`으로 Figure 페이지를 직접 확인한다.
- 논문의 실제 예시(예문·표 샘플)를 찾아 여정에 재사용한다 — 독자가 원문과 대조 가능해져 신뢰가 올라간다.

### 6.3 설계
- 타입 분류 → 등급(A/B/C) 결정 → 존/스텝 목록 → 실험실 조작 축 1개 확정 → 좌표 스케치(viewBox, 존 배치, 라벨 위치).
- 라벨은 도형과 겹치지 않게: 구조도 라벨은 도형 **옆 전용 여백**(예: 오른쪽 x=300~ 열) 또는 도형 아래.

## 7. 정직성 규칙 (전 파일 공통, 타협 불가)

1. **실제 vs 예시의 구분 표시**: 논문에서 추출한 실제 수치는 그대로 쓰고, 시각화를 위해 만든 값(예시 임베딩, 정성 곡선, 가상 가중치)은 반드시 note 캡션에 "정성적 예시/시뮬레이션이며 실제 측정값이 아니다"라고 명시한다. 개별 값 옆에는 "(예시)" 라벨.
2. **계산 가능한 것은 실제로 계산**: 분포(Beta PDF), 스케줄(ᾱ=∏(1-β)), 손실 곡선의 정량 경계 등은 논문 정의식으로 실제 계산해 그린다. "비슷하게 생긴 곡선"을 손으로 그리지 않는다.
3. **note 캡션 필수 구조**: ① 무엇이 예시인지 ② 무엇이 논문의 실제 정의/수치인지(arXiv 번호 포함) ③ 정량 결과는 논문 어디를 보라는 안내.
4. **모르면 비워라**: 논문에서 확인 못 한 세부는 그럴듯하게 채우지 말고 생략하거나 불확실을 명시한다.
5. 방법 서술은 반드시 **원문 확인 후** 작성한다. 기억에 의존해 쓰면 채널 프루닝/가중치 프루닝 혼동 같은 사실 오류가 난다(실제 발생).

## 8. 납품 전 검증 체크리스트 (전부 통과해야 복사)

### 8.1 정적 검사
- [ ] JS 문법: `new Function(scriptText)` 통과
- [ ] `drill`/`DRILL` 문자열 없음 (드릴인 금지 확인)
- [ ] 필수 id 존재: flowpath, 스텝·실험실 요소들
- [ ] 존 개수 == 스텝 개수
- [ ] 등급 A 파일에 cuboid/isometric 잔재 없음 / 등급 B·C 파일에 해당 요소 존재
- [ ] 막대류: 2단계 애니메이션(0→rAF→최종값) + `display:block`

### 8.2 동적 검사 (headless 브라우저 필수)
- [ ] 콘솔/페이지 JS 에러 0
- [ ] **자동 기하 검사**: 모든 SVG의 text·도형 바운딩박스를 실측해 ① 텍스트-텍스트 겹침 ② viewBox 경계 이탈 ③ 텍스트가 무관한 도형에 60% 이상 덮임 — 3항목 모두 0건 (컨테이너 배경 위 의도적 레이어링은 예외)
- [ ] 인터랙션 실측: 슬라이더 값 변경 → 대상 요소의 `getBoundingClientRect()` 실제 변화 확인 (스타일 문자열만 보지 말 것 — style은 100%인데 렌더 폭 0인 버그가 실제로 있었다)
- [ ] 스텝 전체 순회하며 각 미니 시각화 렌더 확인

### 8.3 시각 확인
- 스크린샷을 사람이(또는 비전 가능 모델이) 직접 본다. 기하 검사는 "겹침/이탈/작동"은 잡지만 "어수선함/미감"은 못 잡는다.
- 시각 확인이 불가능한 상황이면 그 사실을 납품 보고에 명시한다.

### 8.4 파일 반영 확인
- outputs 복사 후 **수정 마커(핵심 문자열) grep + 타임스탬프 대조**로 실제 반영을 확인한다. "복사 명령을 실행했다"는 확인이 아니다 — 복사 누락이 실제로 발생했다.
